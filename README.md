# Transformers Docs Copilot

Answers questions about a small, **version-pinned** slice of the official Hugging Face
Transformers documentation, and cites the section each claim comes from. Built as a
first RAG project: keyword retrieval baseline, untuned RAG, then QLoRA fine-tuning for
answer format, citation behavior and abstention.

**Status: Milestone 5 of 6 complete; milestone 6 (human evaluation) in progress.**
Retrieval, the 55-question evaluation set, the grounded-answer pipeline, the untuned 1.5B
baseline and the QLoRA adapter are complete. The remaining work is human scoring of the
tuned label sheet and the final write-up.

## Pinned corpus

- `huggingface/transformers` @ `v5.24.0`, commit resolved at fetch time
- 7 pages, three topics: loading models, text generation, fine-tuning
- 77 breadcrumbed section chunks (~550 estimated tokens each, 15% paragraph overlap)
- Docs are Apache-2.0; see [`docs/DATA-LICENSE.md`](docs/DATA-LICENSE.md) for attribution,
  per-page SHA-256 hashes and scope decisions
- 4 pages feed fine-tuning data, 3 pages are held out for evaluation (but stay in the index)

## Retrieval baseline (BM25, no LLM)

21 hand-written probes; section recall is the headline, page recall is a loose diagnostic.

| metric | @1 | @3 | @5 |
|---|---|---|---|
| section recall | 0.714 | 0.905 | **0.952** |
| page recall | 0.905 | 1.000 | 1.000 |

MRR@5 = 0.819, n = 21. Generated by `make eval-retrieval` into
[`results/retrieval_baseline.md`](results/retrieval_baseline.md) and `.json`.

Known weaknesses the probes expose: no stemming (`tune` ≠ `tuning`), synonyms are
invisible (`lower precision` ≠ `dtype`), and a related section on the same page can
outrank the intended one. One of 21 probes misses at @5 — a synonym question about
precision/dtype — which is the honest case for trying hybrid search later.

## Grounded generation (untuned baseline)

```
question -> BM25 top-5 -> numbered passages -> Qwen2.5-1.5B-Instruct -> parser -> scored row
```

The model must answer with inline `[n]` citations only, or emit exactly
`Insufficient evidence in the retrieved documentation.` It is never asked to write URLs or
a `Sources:` block; the harness renders canonical source lines from the retrieved metadata.
Every output is parsed as untrusted: out-of-range citations are stripped, any model-written
source block is discarded, and a URL in the prose forces an abstention. The model cannot
introduce a URL into the final answer.

`src/eval_answers.py` auto-scores behaviour (answer vs abstain), grounded answers,
citation hits/precision, strict format compliance, repairs and latency, then writes a
report plus a prefilled human label sheet. Support and factual correctness stay manual.

The full 1.5B baseline is committed in [`results/answers_baseline.md`](results/answers_baseline.md).
It is deliberately a floor, not a demo: the model often answers correctly in prose but
ignores the citation contract, so 38 of 43 outputs were forced abstentions.

| metric | value |
|---|---|
| exact format | 0.093 |
| grounded answer (answerable) | 0.000 |
| behaviour accuracy | 0.116 |
| retrieval hit@5 (answerable) | 0.964 |
| model abstains on negatives | 0.267 |
| delivered abstention on negatives | 1.000 |
| median latency | 3.67 s |

That gap — `Answer:` prefix, inline citations, and abstention — is exactly what the QLoRA
adapter targets. The 0.5B CPU smoke run also completes end to end but fails the format for
the same reason. Contract details and metric definitions: [`docs/GENERATION.md`](docs/GENERATION.md).

## QLoRA adapter (milestone 5)

`src/build_sft.py` builds 140 synthetic examples from the four SFT pages only: 85
extractive cited answers and 55 abstention examples. The three held-out test pages never
appear in a training context, and no evaluation question is used for training. Targets are
copied from the cited passage, so the adapter learns `Answer:` + inline `[n]` + abstention
without inventing facts.

`src/train_qlora.py` trains a 4-bit NF4 LoRA adapter (r=16, alpha=32, all linear
projections, 2 epochs, max length 2560). Only assistant tokens are supervised. The adapter
is evaluated with the same 43-question test split via `--adapter`:

```bash
make sft
make train-qlora   # CUDA only
make eval-tuned    # -> results/answers_tuned.md
```

The tuned adapter run is committed in [`results/answers_tuned.md`](results/answers_tuned.md);
the executed run is preserved in
[`notebooks/colab_train_run.ipynb`](notebooks/colab_train_run.ipynb). On the same
43-question test split (T4, commit `5ada516`):

| metric | untuned | tuned |
|---|---|---|
| exact format | 0.093 | **1.000** |
| grounded answer (answerable) | 0.000 | **0.821** |
| behaviour accuracy | 0.116 | **0.930** |
| answered rate | 0.023 | 0.628 |
| model abstains on negatives | 0.267 | **0.933** |
| false abstain (answerable) | 0.964 | **0.071** |
| median latency | 3.67 s | 5.02 s |

All 43 outputs passed the format and there were no parser-forced abstentions. The adapter
over-answered one near-miss negative (`un-10`, default `max_shard_size`) and falsely
abstained on two answerable questions. Three answers cited a related section rather than
the gold section. These are automated contract metrics; support and factual correctness
still require the human label sheet. The 43-row scoring guide is
[`results/review_tuned.md`](results/review_tuned.md); the short scoring sheet
[`results/scoring_tuned_simple.csv`](results/scoring_tuned_simple.csv) contains only the
26 answerable, answered rows with the cited passage and three blank score columns. Data
recipe, hyperparameters and limitations:
[`docs/TRAINING.md`](docs/TRAINING.md).

## Quickstart (local, no GPU)

```bash
make setup           # uv venv + editable install
make fetch           # download pinned pages, write manifest + license note
make chunk           # section-aware chunks with breadcrumbs
make index           # BM25 index
make eval-retrieval  # probe metrics -> results/
make validate-eval   # 55-question quotas + held-out split
make label-sheet     # blank human-scoring sheet
make sft             # 140-example synthetic SFT split
make test            # unit tests
make check           # offline provenance verification

# generation is optional locally; on a CPU-only machine install the CPU torch wheel first
uv pip install --python .venv/bin/python torch --index-url https://download.pytorch.org/whl/cpu
make ml              # transformers/accelerate + the CPU-only 0.5B smoke model

make answer Q="how do I save a GenerationConfig?" MODEL=smoke
.venv/bin/python -m src.eval_answers --split test --limit 2 --model smoke \
  --out-prefix /tmp/answers_smoke --labels /tmp/label_sheet_smoke.csv

.venv/bin/python -m src.retrieve "how do I save a GenerationConfig" -k 3
```

The local machine has no NVIDIA GPU; 4-bit QLoRA training runs on a Colab T4. The local
environment handles ingestion, retrieval, evaluation and a CPU smoke test with a 0.5B model.

## Evaluation set

55 questions, split by page so nothing answerable in `test` was ever used for tuning:

| Split | Answerable | Source pages | Purpose |
|---|---|---|---|
| dev | 12 | 4 SFT pages | prompt/pipeline development |
| test | 28 answerable + 15 abstain | 3 held-out pages | headline results |

The 15 abstain questions are 10 out-of-scope topics (DeepSpeed config, vLLM, GPTQ, tokenizer
training, ...) and 5 parametric-memory traps (Attention paper authorship/year, BERT, GPT-2 XL
parameters, LoRA expansion). All 7 pages stay indexed; held out means "never used to
synthesize fine-tuning data". Rubric and near-miss notes: [`docs/EVAL.md`](docs/EVAL.md).
